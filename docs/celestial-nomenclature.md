# Celestial Nomenclature Design Ledger

## Purpose and authority

This is the real-world authorial record for designing, testing, adopting, and
changing names for stellar systems and the objects within them. It belongs in
`docs/` because it governs the repository's creative process. It is not an
in-world registry, a Blackglass source, or shared setting canon.

A decision recorded here may direct later canon work, but it does not silently
rename an existing object. A new name becomes active only after its change set is
approved, applied across every affected source, validated, and recorded in the
decision log below. Until then, current canon remains authoritative.

This ledger should remain the single starting point for celestial naming. If
candidate research eventually becomes too large for one file, detailed language
and candidate dossiers may move into a future `docs/nomenclature/` directory,
with this document retaining the governing rules and decision index.

## Working vocabulary

Use **Solar System** only for the ancestral system containing Sol and Earth. It
is a conventional descriptive translation, not an independent proper system
name parallel to the names being designed here. Use **stellar system** for the
generic category, including single, binary, and higher-order stellar systems.
Use **planetary system** when the intended subject is specifically the stars'
planets, satellites, rings, and minor bodies.

In informal dialogue, a culture may use *system*, *sun*, or a world-based name
differently. Those usages are aliases and cultural evidence, not reasons to blur
the authorial terms.

## Adopted system-identity model

Every designed stellar system may carry three distinct identity layers.

| Layer | Function | Stability |
| --- | --- | --- |
| **Registry designation** | An unambiguous technical identifier for the system and its hierarchy of bodies. The exact format remains to be designed. | Immutable after adoption. It does not change when proper names, political control, or scientific interpretation change. |
| **Canonical system name** | The principal authorial and common in-world proper name for the whole gravitational and navigational basin. | Stable. It is independent of the names of the system's stars, planets, polities, and routes. |
| **Aliases** | Historical endonyms and exonyms, star-pair names, planet-based metonyms, political usages, translations, censored forms, and colloquial names. | Preserved with provenance. An alias may rise or fall in use without changing the registry identity. |

The canonical system name belongs to the entire stellar system. It does not
automatically name the primary star, the principal inhabited world, its people,
or its government. A single-star system may historically share a name with its
star, but that is an explained exception rather than the default convention.

This structure is intended to survive discoveries and upheavals. A system name
need not change because another stellar component is found, a capital moves, a
planet is destroyed, a polity dissolves, a route is lost, or a different local
name becomes politically dominant.

### Consequences for current names

- **Sol** remains the known name of the ancestral star, and **Solar System**
  remains its common descriptive label. Present cultures generally believe an
  independent proper system name was lost. Authorially, historical Earth never
  had one universal name of that kind. This inversion is established in the
  [human-arrival history](../canon/history/human-arrival-in-kelan-ruva.md).
- **Kelan** and **Ruva** remain the current names of the home system's two stars
  unless later star-naming work changes them. **Kelan–Ruva** remains the active
  canonical system name until a replacement is selected and integrated. Under
  the adopted model, it may later survive as the traditional star-pair name and
  a legacy alias for the independently named home system. Its current physical
  model remains in the [Kelan–Ruva system note](../canon/places/kelan-ruva-system.md).
- **The Valec system** is currently a descriptive, planet-based metonym. Valec's
  containing system requires an independent proper name. See
  [Valec](../canon/places/valec.md).
- **The Issa system** is likewise descriptive. Issa names the gas giant, not its
  star or containing system. See [Issa](../canon/places/issa.md).
- The system containing **Apsis Range** is a distinct system whose name and
  astronomy are deliberately withheld from the represented reader. It may later
  receive an author-only name and registry identity without exposing either in
  reader-facing prose. See [Apsis Range](../canon/places/apsis-range.md).

No accepted name in canon changes merely because these consequences are now
recorded.

## Present system inventory

Current material requires five distinct stellar-system contexts when the
ancestral Solar System is included.

| Context | Present identity | Current naming work |
| --- | --- | --- |
| Ancestral system | Sol is known; “Solar System” is descriptive. A separate proper name is believed lost in-world but never existed authorially. | Retain the inversion. Decide later which particular Solar names and facts were genuinely lost. |
| Home system | Kelan–Ruva | Review and eventually give the whole system an independent canonical name. Preserve appropriate legacy usage. |
| Valec's containing system | No formal name; “the Valec system” is descriptive | Select a canonical system name. |
| Issa's containing system | No formal name; “the Issa system” is descriptive | Select a canonical system name. |
| Apsis containing system | Name withheld or unresolved in reader-facing canon | Decide later whether an author-only name is useful. Preserve the public redaction. |

The first public naming campaign therefore contains three decisions: review the
home system and create names for the systems containing Valec and Issa. Apsis is
a fourth authorial decision only if a private name materially helps later work.

Ninth Holding, Pelar Habitat, Talren, and other presently unplaced offworld
events do not each create a new stellar system. Their withheld locations may
later be assigned to existing or newly designed systems when doing so improves
the history. The authorial target of eight to twelve continuously inhabited
systems is a scale boundary, not a quota requiring immediate names. The relevant
boundaries remain in the [setting scope](../canon/setting-scope.md), the
[engineering landscape](../canon/engineering-landscape.md), and the
[spaceflight and settlement model](../canon/spaceflight-economy-and-settlement.md).

### The Sol inversion

Sol tests the difference between a name, a designation, and a later expectation.
Its astronomical identity, ancestral role, and broad planetary architecture are
known. The common phrase *Solar System* describes the system through its star;
it does not fill the independent canonical-system-name layer adopted for the
present setting.

Contemporary cultures largely assume that the empty layer represents archival
loss. Their own registries make an independent system name seem natural and
necessary. Competing reconstructions may therefore acquire scholarly, political,
or popular constituencies even when they actually recover a name for the Sun, a
planet, a polity, a catalog, a mission, or a local sky tradition.

The belief does not require a coordinated conspiracy. Most people receive it as
an ordinary historical conclusion. Modern data models render absence as a blank
or damaged field; translation makes *Solar System* resemble a generic editorial
label; genuine losses surround it; and incomplete evidence cannot prove that no
Earth culture ever supplied the expected name.

Some institutions and custodians have reasons to maintain the claim or decline
to resolve it. Candidate names support descent narratives, scholarly schools,
commemorations, political legitimacy, archive budgets, and recovery expeditions.
Declaring one candidate correct could privilege one language or carrier lineage.
Declaring that no name existed could discredit institutions and public rituals
built around the search. Deliberate maintenance can therefore range from neutral
ambiguity through motivated silence to an actual lie; future lore must identify
which actors occupy which position.

Authorially, the expected object never existed. There is no concealed correct
answer to the supposed lost name. The genuine losses lie around it: particular
languages and cultural names, incomplete body and feature catalogs, settlements
and habitats, institutions and polities, migration programs, departure points,
and the system's later history. The exact survival ledger remains open for
deliberate development.

## System-name design direction

### Source breadth

Candidate names should range widely across human language. Initial source areas
suggested for research include Wolof, Guugu Yimithirr, Pirahã, Taa (!Xóõ),
Quichean languages, and other languages or historical linguistic traditions
rarely used in English-language speculative fiction.

These are sources of real words and histories, not bins of exotic-looking
syllables. No candidate advances on the authority of an unsourced word list,
automatic translation, or an attractive spelling alone.

### English display form

The canonical display name uses the English alphabet. One word is preferred,
although a multiword form may be considered when its history and rhythm justify
it. Digits, decorative apostrophes, gratuitous hyphens, and diacritics do not
belong in the canonical display form.

The source dossier must preserve the original spelling or transcription even
when the canonical form cannot. If English-letter adaptation removes a click,
tone, glottal distinction, vowel contrast, or other meaningful feature, describe
the result as **derived from** or **inspired by** the source word. Do not present
the adaptation as an exact word in the source language.

### Sound and tone

A selected system name must:

- be pronounceable without specialist training by an American English speaker;
- have one approved plain-English pronunciation, with IPA added when supported
  by the source;
- sound serious in narrative, cartographic, institutional, and spoken contexts;
- avoid accidental comic, childish, obscene, commercial, or conspicuously
  Earth-pop-cultural associations;
- remain intelligible in phrases such as “the ___ system,” “___ approach,”
  “the ___ quarantine,” and “traffic from ___”;
- remain distinguishable from every important existing person, place,
  institution, technology, star, planet, and moon name; and
- support possessive and adjectival use without forcing an awkward demonym.

Ease for an American reader does not authorize a false claim about the source
language's pronunciation. The approved English pronunciation and documented
source pronunciation are separate fields when they differ.

### Meaning and cultural context

A name should have a defensible reason for entering the setting. Its source
meaning may relate to navigation, refuge, distance, paired light, return, loss,
custody, landscape, time, weather, material practice, or another historically
relevant idea. Literal physical description is not required and can become
misleading when scientific knowledge changes.

Reject a candidate when available evidence indicates that it is a slur, a
private or sacred term inappropriate for reuse, a personal name being stripped
of its context, a mistranslation, or a form whose apparently convenient meaning
cannot be supported. When context cannot be established, uncertainty counts
against the candidate.

### Candidate dossier

Every serious candidate should be recorded with:

1. proposed canonical spelling;
2. approved American-English pronunciation;
3. source language or linguistic tradition;
4. original spelling or transcription;
5. source pronunciation, when recoverable;
6. literal gloss and broader contextual meaning;
7. quality and provenance of the supporting sources;
8. whether the proposal is an exact borrowing, transliteration, adaptation, or
   looser inspiration;
9. cultural, sacred, political, insulting, or comic associations checked;
10. existing celestial and Compendium-name collisions checked;
11. the in-world naming history that would explain its adoption; and
12. at least two rejected alternatives and why the selected form is stronger.

A shortlist should be compared aloud and in prose before any choice is treated
as accepted.

## Restricted worlds and restricted names

### Accepted authorial direction

The known region should contain a **small, deliberate handful** of planets with
different degrees and kinds of prohibition. Forbidden status must not become the
default condition of every interesting world.

Possible cases include worlds that are:

- open only under limited scientific, custodial, or diplomatic authority;
- accessible only to specified descendants, lineages, peoples, citizens, or
  other recognized communities;
- protected from settlement or extraction while remote observation remains
  legal;
- quarantined against approach, landing, departure, or sample return;
- interdicted altogether; or
- unreachable in practice even when no surviving authority can enforce a ban.

Each restriction needs its own history, rationale, enforcement mechanism,
exceptions, disputes, evasion, and human consequences. Similar-looking access
rules may arise from biosphere protection, contamination, inherited custody,
burial and memorial claims, treaty settlement, dangerous infrastructure,
political exclusion, population-specific physiology, or deliberate oppression.
They must not be treated as morally or scientifically equivalent merely because
each limits entry.

If an in-world source uses *race*, the authorial record must specify what the
category actually means there: ancestry, kinship, peoplehood, citizenship,
culture, adapted population, asserted biology, or a legally imposed racial
classification. The existence of an access rule does not make its categories
scientifically valid or ethically justified.

### Name knowledge and physical access are separate axes

A planet can be publicly named and absolutely forbidden. Another can be open to
remote science while its historical endonym is restricted. A third can have no
recoverable proper name even though its coordinates and physical properties are
well known.

For every restricted world, track these questions separately:

| Axis | Questions |
| --- | --- |
| **Existence** | Is the body's existence public, classified, disputed, or unknown? |
| **Location** | Are its coordinates, route, and approach geometry public, restricted, falsified, or lost? |
| **Registry identity** | Is a technical designation available even when no proper name is used? |
| **Proper name** | Is the name public, restricted, redacted, disputed, deliberately disused, lost, or known only authorially? |
| **Observation** | Who may observe remotely, and at what resolution or delay? |
| **Approach** | Who may enter the system, local orbit, atmosphere, or surface? |
| **Residence and use** | Who may land, reside, settle, extract, construct, reproduce, or govern there? |
| **Material return** | May samples, organisms, records, artifacts, or people leave? |
| **Authority** | Who claims the rule, who can enforce it, and who rejects that authority? |
| **Duration** | Is the rule permanent, inherited, emergency-bound, periodically reviewed, or merely assumed to be eternal? |

### Working name-availability states

These are authorial distinctions, not yet a canonized in-world vocabulary.

| State | Meaning |
| --- | --- |
| **Public** | The canonical name is ordinarily available and usable. |
| **Designation-only** | A registry identifier is used; no accepted public proper name exists. |
| **Restricted** | A proper name is retained within a defined custodial or eligible community. |
| **Withheld** | An authority or source knows the name but does not disclose it to the relevant audience. |
| **Redacted** | The surviving record visibly removes or replaces the name. |
| **Proscribed** | Use, transmission, or recovery of the name is prohibited. The reason must be stated rather than assumed supernatural. |
| **Deliberately disused** | Institutions or communities intentionally stop reproducing the name without claiming that every memory has been erased. |
| **Lost** | Evidence supports that a name once existed, but no recoverable form survives. |
| **Disputed** | Several forms survive without one accepted canonical in-world name. |
| **Author-only** | The authorial record has a stable name that represented sources do not reveal. |

“Forbidden,” “unknown,” “forgotten,” “redacted,” and “lost” are not synonyms.
Future lore must identify which process occurred, who participated, whether it
succeeded, and what traces remain. A prohibited name is not automatically an
information hazard, magical trigger, true name, or proof that the named world is
supernatural.

### Existing boundary examples

Current canon already demonstrates that the axes can separate:

- [**Valec**](../canon/places/valec.md) has a public name while the destroyed
  world and its approaches are quarantined.
- [**Issa's inner moon**](../canon/places/issa.md) is a prohibited destination,
  but its formal name is not supplied. Current canon does not yet say that the
  name itself is forbidden.
- [**Apsis Range**](../canon/places/apsis-range.md) is publicly named while its
  containing system, coordinates, route, and detailed map remain withheld.

These examples constrain future design but do not pre-fill the intended handful
of forbidden planets.

## Naming and renaming workflow

Renaming is a continuity change, not a search-and-replace exercise.

### 1. Define the decision

Record the object, present canonical name, proposed name, registry identity if
one exists, aliases to retain, authorial status, in-world reason for the change
or coexistence, and which represented sources would know each form.

### 2. Build the impact inventory

Before editing, search for:

- exact spellings, capitalization variants, punctuation variants, and possessives;
- adjectives, demonyms, institutional derivatives, event names, and quotations;
- Markdown links, headings, filenames, slugs, and front matter;
- chronology, glossary, indexes, templates, and editorial companions;
- captions, prompts, diagrams, maps, filenames, and text rendered inside images;
- preserved exemplars whose historical text must not be rewritten; and
- places where the old form should remain as an in-world alias.

The inventory must distinguish files to edit from preserved evidence and files
that merely discuss the former name.

### 3. Approve the migration map

Specify every `old -> new` transformation and every deliberate exception. Decide
whether paths and slugs migrate with the display name or remain stable. A display
rename does not automatically justify breaking stable links.

### 4. Apply one coherent change set

Update canon, entries, frame material, indexes, authorial notes, and assets only
to the extent authorized by the migration map. Do not leave a system half-renamed
across reader-facing sources. Do not rewrite a preserved exemplar to create
retrospective consistency.

### 5. Validate materially

At minimum:

```text
ruby tools/check_repository.rb
git diff --check
```

Then repeat repository-wide searches for every retired spelling and derivative,
inspect the complete diff, and review rendered or generated assets separately.
An image containing an old label is stale even when Markdown validation passes.

### 6. Record completion

Update the decision entry from **accepted** to **integrated**, record retained
aliases and intentionally stale historical forms, and identify any artifact that
still requires regeneration. Commit a single rename or one deliberately cohesive
system batch so that its history remains reviewable.

## Open decisions

The following remain deliberately open for the next rounds of work:

1. the syntax of immutable system and body registry designations;
2. the target length, syllable range, and stress preferences for canonical system
   names;
3. whether each system draws primarily from one linguistic source tradition or
   may have a deliberately layered naming history;
4. the independent canonical name of the home system;
5. the canonical names of the systems containing Valec and Issa;
6. whether the Apsis system needs an author-only name;
7. the later conventions for stars, planets, moons, minor bodies, rings, belts,
   comets, surface features, artificial habitats, and route infrastructure;
8. the number, identities, histories, and precise restrictions of the intended
   forbidden worlds; and
9. which Solar names, catalogs, places, institutions, programs, and historical
   facts survived the founding transmission, remain fragmentary, or were lost.

The next naming session should settle the formal shape of a system name and then
build a sourced candidate set for the home system. No candidate should be chosen
only because it is the first attractive word discovered.
